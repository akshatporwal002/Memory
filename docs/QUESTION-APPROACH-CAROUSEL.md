# Questions: saved alternate approaches

Implemented on `akshat/learning-models`, 5 October 2026. The notebook Questions page keeps its existing renderer, numbering, spacing, source disclosure, edit/menu controls and separators. Question families add centered position dots below their controls. Original is first; left/right gestures or accessible dot buttons show the next/previous saved approach. Only the selected version is rendered. Vertical gestures do not select a variant. Apple gesture/layout validation remains pending Mac connectivity.

Variants target comparable knowledge and reasoning depth. Supported approaches are explain, compare, apply and evaluate. The generation request requires bounded answers, the same prerequisites and source material, distinct reasoning tasks, and individual answer/rubric/objective/source evidence. These are intended difficulty constraints, not empirical calibration. An independent AI source/task/rubric check supplies reviewed specific skill mappings; the learner is not required to review every family manually. Semantic equivalence is not proven by a JSON validator or an AI check. Optional harder progression is notebook-configurable and separately prediction-gated in scored practice.

The existing menu's Prepare/Replace other approaches opens an editable request in the existing assistant. It does not send automatically. The learner sends through their selected authorized provider/model; no new provider, download, paid-call entitlement or background generation is introduced. The new question_variants action inspects versioned original content, retrieves deck-scoped evidence and presents a native scrollable review of each question, answer, objective, rubric and source. Explicit acceptance saves the family through the existing journal/undo boundary. Swiping never invokes generation.

Optional QuestionFamily data is stored on the original Note, so existing libraries decode unchanged and families persist with the library offline. Save validates distinct approaches, bounded content, current unchanged original, current library revision and exact retrieved source identities/text/versions. Stale source variants are hidden. Original front/back/source edits invalidate the family. Variant edits use a separate editor and require renewed review, leaving original FSRS cards untouched. Families are currently supported for basic questions only.

Variant exposure is recorded once on browsing because answers are visible. Exposure is separate from attempts/reviews; no grades, mastery updates or scheduling resets occur. Validated saved variants now enter separate scored understanding sessions, with rotation, compatible model selection, batched assessment and same-attempt corrections. Known exposure prevents claiming unfamiliar transfer; absence of a browsing record does not establish novelty. See [understanding practice](UNDERSTANDING-PRACTICE.md).

Backend checks cover JSON reload, offline availability, exposure without reviews, source rejection, duplicate rejection, original-edit invalidation and unchanged actual FSRS card states. Existing learner-model replay/switching/isolation/fitting tests remain in the same validation runner. UI source syntax can be checked on Windows; full Apple compilation/device checks require the Mac and canonical caches. No simulator or app data is altered. No commits or pushes.

Final Windows run: PASS for production backend module boundaries, UI Swift syntax and all new/existing backend assertions. Compilation, signing, installation and launch on Apple platforms were not performed: `codex-mac` fails hostname resolution. No paid/cloud inference was exercised. Known compiler outputs were removed by the runner; reusable `.build` was retained, with no substantial temporary storage created.
