# Review, maths, tutor and research implementation decisions

Started 5 October 2026 on `akshat/review-maths-tutor`.

The user authorized unattended implementation and asked for critical decisions to be recorded for morning review. Existing unrelated edits must be preserved.

- Batch size defaults to five and is adjustable from 1–10 in Study settings. Remaining answers flush when leaving/finishing study; saved work resumes in foreground after restart.
- Reference answers display after submission by default. AI marking runs separately; post-submission reveal does not make the saved original attempt assisted.
- Supported grades commit automatically at original submission time. Unclear/failed attempts require attention. Summary notifications are in-app, dismissible and never force navigation; unseen finished feedback persists and accumulates.
- Maths notebook defaults are Off / Basic / Advanced. Maths applicability comes from explicit question metadata/tags, not guessing every short-answer question is mathematical.
- TI-style keyboard uses the referenced compact rectangle, not a replica of TI hardware. Ctrl/Shift replace visible key faces; ABC opens letters; x/y/z are directly available. Mathematical notation uses conventional glyphs; special tool icons use system symbols. No solver is added.
- Tutor activation automatically reuses one workspace. Tutor assignments are a separate model, excluded from personal study queues. Search covers authorized student display names and assignment subjects.
- Payment is checked at invitation time, not when creating draft work. Unverified entitlements cannot grant paid tutor access.
- Research consent is off initially. Metrics and raw answer/transcript consent are separate; the user explicitly approved adding the latter opt-in. Individual records retain for 12 months; research access initially remains owner/admin only. Secrets, raw audio and unrelated documents are excluded.
- Existing tutor/guardian sharing boundaries remain in effect. UI activation alone cannot grant student access.

## Validation and actual completion

The implementation is on `akshat/review-maths-tutor`; existing unrelated edits were preserved. No production purchases, paid provider calls, or phone installation were performed during this task.

- Typed review now uses plain input and faint dividers. Submission is saved and advances the queue before AI returns. Batch preferences, reference reveal, saved feedback, retry, manual review and disputes are implemented. Repository write conflicts retry the already-returned assessment rather than repeating an AI call.
- Grading preserves the submission time and replays later reviews when a disputed grade changes. Exact local marking is conservative; missing/invalid batch results remain for manual review or retry. Summaries count actual committed FSRS grades: Again / Hard / Good / Easy.
- Voice capture requires confirmation of each transcript. Recognition currently supplies no reliable word-confidence metadata, so the app does not fabricate red uncertainty marks or contextual guesses. The confirmed text joins deferred marking; audio is not research content.
- The maths keyboard stays on the question screen and does not bring up the system keyboard. Ctrl/Shift, letters, x/y/z, fraction slots, cursor navigation, advanced notation and matrix/piecewise dimensions are supported. Explicit question type survives note editing. No equation solving is added.
- Tutor workspace activation and Library access, notebook drafts, subject grouping, student search and assignment-scoped progress presentation are implemented. Progress is keyed by assignment, not student; withdrawn/superseded assignments are excluded. Tutor drafts do not enter personal review queues.
- **Hosted tutor invitations, payment verification and live student sharing remain dependencies.** The UI states these limits instead of granting access from local activation or inventing students. No fee is charged on activation. Server-verified invitation entitlement is required before enabling real invitations.
- Research implements a fixed consent-gated event model, durable account-scoped queue, 12-month expiry, withdrawal/content stripping, question type/schema/modality, review grades and later corrected reviews, foreground question exposure, AI queue/response/first-token times, and provider token usage when available. Missing token usage is explicitly an estimate, never reported as measured. Visible time is an exposure estimate, not attention. It excludes reference reading, background time and other pages.
- **Research upload remains disabled.** `supabase/migrations/20261005010000_research_events.sql` is a prepared migration, not an executed migration. The available Supabase connector cannot access Engram project `heedprsusmrwxasdixbt`; the unrelated exposed project was untouched. The database migration, permissions verification and periodic expiry job must be deployed before enabling `EngramResearchUploadEnabled`. Default consent stays off. Raw answer/transcript collection additionally requires its separate opt-in.
- Research currently instruments the supported review routes. Subject/subtype use explicit `subject:` and `subtype:` tags; maths notation/tags identify the maths domain without turning a maths MCQ into an equation-input question. These fields are snapshotted in attempts/reviews rather than reread from later edits. Unknown subjects stay unknown. This is not a full subject taxonomy, every proposed event, all new question renderers or a complete research dashboard. Tutor research does not expose raw answers to tutors.
- No PC stay-awake helper was launched, so there is no task-created helper to stop. Existing unrelated processes were left alone.
